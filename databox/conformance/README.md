# DBX-27 — Interoperability & conformance

The release gate for interoperability: **≥2 independent, non-Databox Solid clients plus a reference
agent, exercised against the packaged deployment**, with a compatibility manifest and a conformance
report. No requirement is marked *passed* on the strength of existing code — every row is backed by a
live HTTP assertion in `test/integration/DataboxConformance.test.ts`.

## Artifacts

- `dbx-27-conformance.json` — the machine-readable conformance report, **regenerated by the test run**
  (each requirement → `pass`/`fail`/`not-applicable` + the observed HTTP evidence). It is an emitted
  artifact, not hand-maintained; `git` may show it dirty after each run — commit the latest.
- `dbx-27-conformance-report.md` — the human-readable report + compatibility manifest summarising the
  same evidence.

## How to regenerate

```bash
npx jest test/integration/DataboxConformance.test.ts
```

## What is proven live

| Requirement | Evidence |
|---|---|
| WebID profile resolvable to RDF (both clients) | `GET <webId>` → 200 |
| ≥2 independent Solid-OIDC clients authenticate + read own pod | `GET <pod>` → 200 each |
| Standard LDP PUT/GET (bytes preserved) | PUT → 201, GET → 200 + body |
| Cross-client isolation (private resource unreadable) | bob GET alice/doc → 403 |
| ACL-governed sharing grants a second client read | bob GET (after .acl) → 200 |
| ACL read-only grant still denies write | bob PUT → 403 |
| Reference agent (third client identity) round-trips | agent PUT → 201, GET → 200 |
| Ordinary Solid surface coexists with the databox control plane | GET / → 200; GET /.databox/smithy/programs → 401 |

The three client identities are `alice-conformance-client`, `bob-conformance-client` (independent
WebIDs) and `reference-agent-client` (a distinct client_id) — proving the deployment serves arbitrary
Solid-OIDC clients rather than a single baked-in one.
