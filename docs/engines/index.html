A decision guide for two optional engines

Same portable records. Different tools, terms and capabilities.

Web Civics Databox can use more than one underlying engine. This choice affects what the system can do, where it runs, and the legal and economic terms under which its creators make it available. It should not change who owns the record.

The key point

Accepted Databox records remain standard Solid RDF records. Solid is an open-standards protocol: it gives compatible servers a common way to identify, describe and exchange data across the web. An engine works with those records; it does not own them. Its creators retain the right to set fair terms for their work.

Before comparing

Start with the information people need, then choose an engine on fair terms.

Think of the Databox as the filing system and an engine as a specialist tool used with that filing system. Both engines can work with information represented using open RDF web standards. The important records are kept in the Databox’s standard storage so that they can be moved or checked without being trapped in one engine.

This is why the comparison is not a competition. Oxigraph and Qualia are useful for different jobs, and a group can choose neither until there is a clear need. A source-available or open-source licence is not a claim that its authors, maintainers or support workers owe their labour, hosting, electricity, equipment or expertise for nothing.

The Web of Data

Like the web of pages, but for information that systems can understand together.

What Solid contributes

Ordinary web links connect one page to another. The Web of Data uses web addresses and shared data formats to connect information: for example, a person, a community project, a receipt or a service can each have a meaningful address and a clearly described relationship to the others.

Solid adds a permission-based way for people and organisations to keep this information on compatible servers. A Databox can therefore interact with another Solid server without both parties having to use the same supplier or database product. Permission still matters: compatibility is not a right to access somebody else’s information.

What Qualia contributes

Qualia works with these Solid and RDF protocols and adds richer ways to validate, reason over and produce evidence about information. It can check declared rules, trace a calculation, handle conflicting claims carefully and help move selected information between Qualia and Solid in a controlled way.

In other words: Solid helps compatible services exchange and link information; Qualia can add advanced logic and decision-evidence features while keeping that information connected to the wider Web of Data.

Qualia’s advanced Web Civics features

More than a graph store: a decision-evidence engine.

The Web Civics Qualia WASM profile is intentionally broader than a database query engine. Its advanced features are designed to make decisions, evidence and boundaries inspectable. They do not make decisions on behalf of people.

Rules, rights and responsibilities

It can evaluate permissions, obligations and prohibitions; reason about stated knowledge; and check agreement, rights, consent and harm boundaries. This supports reviewable rules rather than hidden automated judgment.

Reasoning when information conflicts

Paraconsistent routing can isolate a contradiction instead of treating it as a reason to discard everything. Temporal logic, description logic, answer-set and linear logic provide tools for checking sequences, categories and resource commitments.

Evidence that can be checked

It can validate RDF with SHACL, use pinned JSON-LD contexts and produce capability and computation receipts. This helps reviewers establish what rules, data form and engine capabilities were used in a result.

Careful analysis, not black-box prediction

Its Web Civics profile includes descriptive statistics, regression verification and diagnostics, economics and welfare calculations, exact arithmetic, numerical methods and linear algebra. Outliers are flagged for review, not silently deleted.

A local database in an installed web app

When Qualia is used as an installed WebAssembly/PWA application, it can keep a persistent local Qualia vault/database in the browser’s OPFS storage area. This is application data on the person’s device, not merely a temporary page cache.

Personal continuity and migration

The local database can be backed up to a user-selected folder and restored after a device or browser problem. It also supports leave-and-return paths between Qualia and Solid. Sensitive sanctuary information requires an explicit choice before export; classified information must not leave.

Deliberately limited browser profile

This particular WASM build excludes GPU/WebGPU, GGUF and generative LLM functions, full homomorphic encryption and native-device features. Its published capability list should be checked before any deployment claim is made.

Installed app capability

A browser-based app can still have a real local database.

What happens on the device

When a person installs a Qualia-powered web app, the WebAssembly engine can use the browser’s Origin Private File System (OPFS) to keep the local Qualia vault/database. It stores its own durable data blocks there, rather than depending only on a web page remaining open.

This allows a person to work with their information locally in an installed app. It is useful where people want a personal device-based vault, including situations with intermittent connectivity.

What it does not mean

The database remains tied to the person’s browser and device until they back it up or migrate it. It is not automatically a public website, a shared cloud database or a substitute for a backup plan.

Qualia’s Web Civics profile includes a backup-folder link and verification process. When information needs to interoperate with a Solid service, Qualia can project the selected information into standard Solid RDF while respecting the required sanctuary choices.

Interoperability comes first

Qualia’s internal formats can make advanced local processing efficient, while Solid-friendly RDF formats keep selected information able to interoperate across the Web of Data. What “symbolic AI” means

AI that works with stated facts, concepts and rules.

Symbolic AI, in plain language

Symbolic AI represents things explicitly: “this person is eligible”, “this rule applies until this date”, “a guardian may view but not decide”, or “these two claims conflict”. It then follows declared rules and relationships to test a conclusion. The value is that a reviewer can inspect the facts and rules used.

Qualia’s logic, validation, rights, consent, temporal and contradiction-handling tools are symbolic-AI capabilities. They can support a decision process, but they do not remove the need for a human decision-maker who is accountable for the outcome.

How this differs from the AI people usually know

When people say “AI” today, they often mean a generative language model: a system trained to recognise patterns in large amounts of text and generate likely words, images or code. It can be useful for drafting, explaining or helping someone find information, but its answer is not automatically a verified rule or a reliable record.

The two approaches can complement each other. A generative tool may help a person ask a question in ordinary language; symbolic AI can then check permissions, apply declared rules and provide a reviewable trail. The current Web Civics Qualia WASM profile does not itself include a generative LLM or GPU runtime, so any such tool must be separately chosen and governed.

A sensible boundary

Use generative AI to assist people with language and exploration. Use explicit rules, evidence and accountable human review for decisions that affect people’s rights, services, money, safety or dignity.

Licence choices matter

The engines have different terms of use — and both deserve respect.

A core Web Civics Works principle is that people must be able to be paid fairly for their work. This includes the people who design, build, host, maintain and support technology for communities. The value created by code, data, knowledge, care work and computing infrastructure must not be treated as something that can be taken without meaningful consent, recognition or a fair opportunity to agree terms.

Oxigraph

Permissively licensed open-source choice

Oxigraph is offered under your choice of the MIT licence or Apache License 2.0. Those licences grant broad permissions subject to their terms and notices; they do not erase the cost or value of the people and resources behind a deployment.

Practical implication: an organisation may use this licence path where it suits its policy, while still budgeting fairly for implementation, maintenance, security, support, hosting and energy.

Web Civics Qualia (WASM)

Purpose-bound, separately licensed choice

The named wasm-webcivics engine binary is proprietary freeware with a Web Civics Databox field-of-use restriction. It may be used only as the authorised integrated Databox component and must travel with its licence. This boundary protects the creator’s stated conditions for the advanced engine rather than making its work available for unbounded extraction.

The Databox bridge source is separately licensed under CC BY-NC-ND 4.0. It is not covered by the Databox repository’s MIT licence.

Practical implication: obtain a licence review and, where needed, an appropriate agreement before procurement, redistribution, commercial use, changes or use outside the authorised Web Civics Databox ecosystem. Do not assume that another party’s code, computing resources or specialist work is free to take.

Rejecting digital slavery

Digital slavery includes systems that extract labour, data, creative work, hosting, computing or support from people while denying them meaningful choice, credit, bargaining power or fair compensation. A choice is not meaningful when a person risks losing income, housing, care, safety, essential services or their ability to live with dignity by refusing. A responsible deployment budgets for the real work behind it and works toward protecting economic rights. This is an ongoing social, technical and governance objective—not an easy binary fix—and its direction is clear: basic needs should never depend on giving away a person’s work, data or future.

A protection that applies to both

Sensitive information must not be moved silently.

Qualia’s migration path includes a deliberate choice when restricted “sanctuary” information is present: leave it behind, or explicitly reclassify it before creating a Solid export. Classified information must not be exported. This is a useful governance rule regardless of which engine is chosen.

Choosing a path

A simple starting recommendation.

Choose Oxigraph first when…

Your immediate need is standards-based RDF search or reporting, and you want the clearest open-source licence path.

Explore Qualia when…

You have a specific requirement for its decision-evidence capabilities or Qualia leave/return workflow, and can meet the separate licence and deployment conditions.

Pause the engine choice when…

The service purpose, information boundaries, support model or governance responsibilities are not yet clear. Start there; no engine fixes an unclear service.

A good committee resolution

“We will keep our essential records in portable Solid RDF so they can interact, by permission, with compatible Solid services in the Web of Data. We will use optional engines to add stated capabilities — including Qualia’s advanced logic and decision-evidence features where appropriate — and approve each component only after its licence, support, security, human-rights and exit arrangements have been reviewed.”
